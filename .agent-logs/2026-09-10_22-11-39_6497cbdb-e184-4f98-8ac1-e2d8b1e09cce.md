## Endpoints (`apps/api/src/bookings/`)

| Route | Role | Notes |
|---|---|---|
| `POST /bookings` | COMPANY | Body `{creatorProfileId, package: "single"\|"bundle", deliverable}`. Resolves company → active campaign (404 if none). **Price is computed server-side** from the creator's real `postCostCents`/`bundle5PriceCents` — the client only sends which package was selected, never a raw cents figure, so price can't be tampered with. Rejects with 409 if a non-DECLINED booking already exists for this creator+campaign (schema has no unique constraint, so I'm guarding against silent duplicates at the app level). |
| `GET /bookings/received` | CREATOR | Own `creatorProfileId` resolved from the token — no client-supplied id accepted, so there's no IDOR surface at all. Paginated, enriched with campaign/company name for the UI. |
| `GET /bookings/sent` | COMPANY | Own company's bookings (joined through campaign), paginated, optional `?campaignId=` filter. |
| `PATCH /bookings/:id/status` | CREATOR | Body `{status: "ACCEPTED"\|"DECLINED"}`. 404s (not 403) if the booking isn't the caller's own — doesn't confirm existence. 400s if it's not currently INVITED. |

All four behind `JwtAuthGuard` + `RolesGuard` + `@Roles(...)`.
