```ts
export interface AttributionRow {
  creatorProfileId: string;
  creatorDisplayName: string;
  bookingsCount: number;   // every booking this brand made with them, any status
  totalClicks: number;
  qualifiedClicks: number; // ClickEvent.isLead — the second number
}
export interface AttributionResponse extends Paginated<AttributionRow> {
  hasAnyClicks: boolean;   // computed over the full result set, not just the page
}
```

**Second number:** I picked **qualified clicks** (`ClickEvent.isLead`) over the field, not clicks-per-booking or CTR. It's already in the schema, RECON's own Results page uses the "qualified clicks" framing, and it's a real quality signal for "book again" — a creator with fewer raw clicks but a higher lead rate is arguably the better call. Rows sort by `totalClicks` desc, then `bookingsCount` desc.

**The aggregate query** — done in-memory over per-creator rows (same justification the codebase already uses for the ~40-row creator catalogue: this scopes to one brand's booked creators, smaller still):
1. `booking.groupBy({ by: ['creatorProfileId'], where: { campaign: { companyId } } })` → bookings count per creator (all statuses — mirrors what Collaborations already lists).
2. `booking.findMany` where `trackedLink: { isNot: null }` → map `trackedLinkId → creatorProfileId`.
3. Two `clickEvent.groupBy({ by: ['trackedLinkId'] })` calls scoped to those link ids — one plain, one `where: { isLead: true }` — for total and qualified counts per link.
4. Fold link-level counts up to creator level, join in `creatorProfile.displayName`, sort, compute `hasAnyClicks`, paginate the array.

**Honesty handling** — two distinct empty states, not one generic "no data":
- Zero bookings at all for the brand → "No bookings yet" state (mirrors Collaborations' own empty copy), links to Marketplace.
- Bookings exist but `hasAnyClicks` is false → a specific "no clicks yet" finished-state message, instead of rendering a table of all-zero rows that would read as broken. `hasAnyClicks` is computed over the whole result set server-side so page 2 of a paginated table can't wrongly trigger this.
